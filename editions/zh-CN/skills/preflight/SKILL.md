# Preflight

## 定位

`preflight` 在行动前先向外看、向后看：别人尝试过什么，哪些做法有效，哪些失败已经发生，现成语言与能力在哪里。

核心动作：

1. 站在前人肩膀上。
2. 提取适合当前目标的精华。
3. 舍弃过时、失真、噪音过大或情境不匹配的部分。
4. 回到当前任务，给出更清晰的下一步。

这是第一轮路由闸门，负责粗粒度扫描、路线判断和下一步收敛。深度研究、方案融合、详细设计、实施和任务收尾交给对应能力。

## 适用场景

- 功能、产品、插件、工作流、Agent 能力、内容、研究或业务问题可能已有前例。
- 用户询问竞品、替代方案、已有解法、开源选项、平台原生能力、概念、类比或基准。
- 术语和前例可能改变当前计划。
- 实施成本较高，短扫描可以减少重复工作。
- 用户明确要求先查外部世界。

## 可跳过场景

- 只需完成很小的本地编辑。
- 用户已选定技术，只需要最新官方用法。
- 用户从一开始就要求深度、可审计的研究交付。
- 答案完全存在于当前仓库，应直接检查仓库。

## 默认时间盒

- 10–20 分钟。
- 5–8 个高信号前例、选项或概念。
- 涉及网络研究时，每个主要类别优先保留 2–4 个一手或高质量来源。
- 当前仓库、工作区或历史决定相关时，增加一次本地检查。

当新增材料已经无法改变建议时停止。

## 路由

| 任务实质 | 后续能力 | 原因 |
|---|---|---|
| 多个已知方向需要形成一个自有方案 | `fusion` | 需要取舍、重组与一致的新路线 |
| 同一问题需要沿目标、参与者、系统和行动追踪 | `scale` | 需要先选择可行动边界 |
| 学术文献或系统综述 | 学术研究工作流 | 需要可复现检索、方法、引用与偏差处理 |
| 竞品或市场分析 | 竞品研究工作流 | 需要围绕真实选项组织证据 |
| 已选技术的当前最佳实践 | 官方文档与版本感知的技术工作流 | 需要最新一手资料 |
| 产品需求、设计或实施 | 对应的产品、设计、架构或工程工作流 | 方向已经足够清晰 |
| 计划、规格或交接仍有关键歧义 | 需求拷问或评审工作流 | 目标、验收、边界和假设需要核实 |

路由成立时，明确写出接力问题。

## 最简可行路径

面对编码或自动化任务，按顺序检查：

1. 这个能力是否需要存在？
2. 当前仓库、工作区或本地成果是否已经解决？
3. 标准库、平台、宿主应用或操作系统是否已经提供？
4. 已安装依赖或已配置工具是否已经提供？
5. 配置、包装或组合能否满足需求？
6. 确认以上路径不足后，再建议最小自定义实现。

## 工作流

1. 用一句话复述要在行动前核实的能力、决定或问题。
2. 判断前例属于产品、开源项目、平台能力、学术概念、商业类比、内容模式、流程模式或本地前例。
3. 选择继续轻量扫描，或交给专业工作流。
4. 当前仓库、文档和历史决定相关时，先查本地材料。
5. 公开信息、时效或生态变化可能改变决定时，再查网络。
6. 优先使用官方文档、源代码仓库、发布说明、标准、论文、产品页、价格页和一方案例。
7. 对实施型任务执行“最简可行路径”检查。
8. 从匹配度、成熟度、集成成本、体验、约束、风险、可借鉴部分和可省略工作比较选项。
9. 计划、规格、工单或交接将进入执行时，核实未解决的目标、验收、边界、备选方向和假设。
10. 说明本次扫描改变了什么，并给出最小下一步。

## 证据要求

- 一手来源优先。
- 第三方评论只作补充信号。
- 快速变化的产品、接口、插件和依赖要写明日期或版本背景。
- 间接证据形成的判断要标记为推断。
- 旧记忆或历史笔记需要重新验证，才能代表当前状态。
- 无法访问实时网络时，明确说明结论只来自本地材料，可能已经过时。

## 决策词

- **自建**：现有选项无法满足，或差异化要求掌握核心能力。
- **适配**：已有模式或开源项目接近目标，需要调整。
- **集成**：成熟外部选项以更低成本满足需求。
- **包装**：平台已有能力，需要补充工作流、界面、自动化或连接层。
- **路由**：专业能力更适合处理下一步。
- **暂缓**：价值证据弱、风险高或目标仍不清楚。
- **缩小**：保留想法，以复用、配置或更薄的实现开始。

## 输出

```markdown
**开工前问题**
<行动前要核实什么>

**外部地形**
<已有能力、前例及问题类别>

**相关前例**
- 名称：用途、可借鉴部分、应舍弃部分、证据质量。

**提取精华**
- 可复用的原则、接口、体验、流程、商业动作或约束。

**舍弃部分**
- 过时模式、过度建设、误导类比、弱证据或范围外内容。

**路由**
- 继续当前扫描 / 交给某项能力 / 扫描后接入某项能力。

**最简可行路径**
- 省略 / 复用 / 标准库 / 原生能力 / 已有依赖 / 包装 / 最小自建。

**建议**
自建 / 适配 / 集成 / 包装 / 路由 / 暂缓，并写明下一步。
```

## 红线

- 查清前例后再评价创新程度。
- 每个选项都要连接当前决定，避免堆砌知名工具。
- 研究服务行动，建议稳定后及时停止。
- 关键歧义没有解决时，先评审再实施。
- 编码任务先检查复用和原生路径。
- 安装、构建、迁移、大型抓取或部署需要遵守长操作审批门槛。
