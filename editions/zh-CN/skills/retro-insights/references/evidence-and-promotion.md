## 证据等级

| 等级 | 证据 | 可支持的结论 |
|---|---|---|
| A | 真实文件、git、测试、日志、命令结果、可打开入口、明确用户纠正 | 事实和高置信行动 |
| B | 多个独立用户根会话中一致出现的行为或结果 | 趋势和重复模式 |
| C | Memory、Chronicle、截图、UI 状态、摘要 | 路由与待验证假设 |
| D | 单次推断、模糊印象、邻近窗口 | 不能晋升，只能提出验证问题 |

来源多不等于证据强。十条同源摘要仍可能只是一个事件。

## 模式卡

为每个候选模式记录：

```text
模式：
事实证据：
不同用户根会话数：
领域：代码 / 产品PM / 协作与文档 / 设计 / 环境配置 / 自动化 / 交付 / 其他
影响：时间 / 质量 / 风险 / 信任 / 成本
反例：
根因置信度：低 / 中 / 高
当前状态：观察 / 关注 / 晋升候选 / 已实施 / 已验证 / 已撤回
```

同一会话中的多次重复只算一个独立会话证据。subagent、guardian、automation 和技术探针不能替代用户根会话证据。

## 晋升阶梯

### 观察

- 只出现一次，或只有 C/D 级证据。
- 保留在报告，不改系统。

### 关注

- 出现于两个不同用户根会话。
- 下一周期主动寻找反例、影响和根因证据。

### 晋升候选

满足任一条件：

- 至少 3 个不同用户根会话，且跨至少 2 个领域；
- 同一高风险问题重复两次且有 A 级证据；
- 用户明确要求长期执行；
- 一次事件造成显著不可逆损失，且防护规则明确、低成本、可验证。

### 已实施

- 用户批准落点和改动。
- 备份优先、最小 patch、精确回读。

### 已验证

- 下一周期同类错误减少，或新流程产生明确正向证据。
- 如果无效，撤回、缩小或改为项目级规则。

## 落点选择

| 洞察类型 | 首选落点 |
|---|---|
| 跨所有项目的稳定协作边界 | 用户级 Agent 规则 |
| 单一项目事实、术语、命令、业务边界 | 项目级规则或项目状态文档 |
| 重复的多步方法 | 新 Skill 或现有 Skill 最小更新 |
| 可机器判定的危险动作或前置条件 | hook / validator / script |
| 周期性检查与报告 | automation |
| 故障恢复、Owner、监控、回滚 | runbook / postflight 文档 |
| 仍不稳定或只出现一次 | 只留 retro-insights 报告 |

不要把项目细节提升到全局；不要把可执行检查写成冗长提示词；不要为每个洞察创建新 Skill。

## 周期对比

下一份报告必须回看上一周期最多 3 个行动：

| 状态 | 判断 |
|---|---|
| 有效 | 有 A/B 级证据显示问题减少或质量提升 |
| 无效 | 已执行但指标、行为或结果无改善 |
| 未执行 | 行动尚未发生，不评价方法本身 |
| 证据不足 | 无法观察或窗口太短 |

连续两个周期未执行的低价值建议应删除，不自动滚入 backlog。
