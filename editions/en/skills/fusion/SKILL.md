# Fusion

## Purpose

`fusion` turns understood material into a new whole. It preserves useful principles, structures, mechanisms, and tradeoffs while rebuilding them around the user’s own goal and constraints.

The Skill starts after enough source material exists. `preflight` finds precedents. `scale` chooses the working boundary. `fusion` digests differences and forms one coherent route.

Its output should read as the user’s solution. Source labels remain only where evidence, attribution, licensing, or risk requires them.

## Use When

- Several references, frameworks, proposals, drafts, or products each contain useful parts.
- The user wants to learn from others and still create a distinct method.
- Existing material feels fragmented, contradictory, repetitive, or too attached to its original context.
- A new whole is needed for a product, workflow, architecture, policy, article, presentation, or decision.

## Skip When

- The landscape has not been explored; use `preflight`.
- The working boundary is still unstable; use `scale`.
- One clear option has already been selected and only implementation remains.
- The user needs a citation-led comparison without synthesis.

## Input Contract

Establish:

- target outcome and intended audience;
- working boundary and non-goals;
- source material and its evidence quality;
- constraints, values, risks, and irreversible choices;
- what must remain distinct or attributed;
- acceptance criteria for the new whole.

When source material is incomplete, identify the missing evidence and continue only if a transparent assumption will not distort the direction.

## Fusion Process

### 1. Anchor the Goal

Write the outcome in one sentence. Every borrowed element must serve this goal.

### 2. Decompose Sources

Reduce each source into:

- core claim or mechanism;
- useful principle;
- structural pattern;
- operational step;
- enabling condition;
- hidden assumption;
- tradeoff and failure mode;
- evidence strength.

### 3. Sort the Material

Classify each element:

- **Essence:** transfers well and strengthens the goal.
- **Conditional:** useful only under stated conditions.
- **Dross:** stale, weak, redundant, overbuilt, or mismatched.
- **Noise:** attractive detail with no effect on the decision.
- **Protected:** must retain attribution, license terms, or clear separation.

### 4. Find Tensions

Name contradictions among sources and between the sources and the user’s context. Resolve each tension through priority, sequencing, scope, conditional branching, or an explicit tradeoff.

### 5. Rebuild Around the Goal

Create a new structure from the selected mechanisms. Define:

- governing idea;
- key modules or stages;
- operating sequence;
- decision rules;
- interfaces and handoffs;
- evidence and acceptance;
- deliberate omissions.

### 6. Make the Whole Coherent

Check:

- **Wholeness:** every major part supports the goal.
- **Consistency:** terms, assumptions, rules, and interfaces agree.
- **Credibility:** evidence and uncertainty are visible.
- **Ownership:** the result reflects the user’s choices and context.

### 7. Choose the First Test

End with the smallest action that can test the fused solution and the signal that would confirm or challenge it.

## Quality Bar

- Every conclusion connects to the current goal and contains a clear choice.
- Borrow at the level of principles, structures, processes, or decision criteria.
- Resolve contradictions and avoid feature collage.
- Keep source labels only where evidence or attribution needs them.
- State missing evidence openly.
- Narrow the use of material when licensing, privacy, legal, or commercial risk remains unclear.
