# Scale

`scale` 是沿关系移动的动词。它围绕同一关注点寻找当前可行动的工作边界，省略“个人级、项目级、企业级”等固定标签。

在 `preflight` 已找到前例和方向后、进入具体方案前，沿同一件事的关系、因果、约束和反馈来回缩放，直到找到一个既保留关键联系、又足以行动和验收的临时工作边界。

`scale` 聚焦缩放、边界选择和后续路由；研究、方案融合、PRD、设计、架构、实施和 `postflight` 由对应能力继续处理。治理结构来自关系追踪的结果。

## 基本观念

- 宏观和微观描述观察距离；缩放改变前景与背景。
- 一个对象可以同时是整体、另一整体的部分，也可以横跨多个重叠系统。
- 真实结构通常呈现为重叠网络；横向关系需要保留。
- 边界是服务当前决策的临时假设，并随新证据接受修订。
- 获得最小充分证据后停止，把“万物相关”留在工作边界之外。

## 输入

优先读取 `preflight` 结论、用户目标和已有材料。确认：

- 当前关注点：正在理解、决定或改变什么；
- 期望结果：什么变化才算成立；
- 已知关系：目标、参与者、系统、数据、工具、权限、风险和外部影响；
- 已有证据：哪些是事实、推断和未知；
- 用户边界：明确要求只处理什么、暂时不处理什么。

信息不足但不改变缩放方向时，写明假设并继续。只有缺失信息会改变目标、权限、关键边界或结果时，才提出最多三个短问题。

## 缩放循环

始终围绕同一关注点移动，并保持关注点名称稳定。

1. **锚定关注点**：用一句话写明当前要理解、决定或改变的同一件事。
2. **向外缩放**：沿真实连接追踪更大的目标、必要输入、决策权、共享系统、下游影响、反馈和时间跨度；不要直接跳到抽象的“上一级”。
3. **向内缩放**：沿结果形成的因果链追踪判断、动作、材料、接口、交接、失败点和完成证据；不要按岗位名称拆分。
4. **横向追踪**：寻找重叠工作流、共享资源、循环依赖、共同约束，以及局部优化向别处转移的成本和风险。
5. **比较镜头**：识别不变量、突变、耦合和盲点。
6. **返回关注点**：判断新增信息是否改变当前决定；必要时再次缩放，否则选择工作边界。

每次比较四件事：

- **不变量**：哪些目标、矛盾、约束、反馈模式或完成定义始终没有改变；
- **突变**：哪里出现新的权限、风险、时间节奏、专业语言或因果机制；
- **耦合**：哪些部分必须一起判断，哪些关系可写成输入、输出、约束或反馈；
- **盲点**：当前镜头暂时遮蔽了什么，是否会影响行动。

相同模式在不同尺度反复出现时，复用同一任务契约，不增加层级名称。机制确实变化时，标记突变并路由给相应专业能力。

## 停止与工作边界

向外缩放，直到新增关系不再改变目标、权限、主要风险、验收或当前行动。向内缩放，直到下一步已可独立执行和验证，继续细分只会制造管理负担。

当前工作边界还应满足：

- 包含关键因果链和紧耦合关系；
- 外部依赖已写成输入、约束、接口、审批或反馈；
- 没有越过用户的范围、权限和风险边界；
- 边界内的工作能够被分配、执行和验收。

写明为什么在这里停止。不要把临时工作边界描述成固定规模等级。

## 治理与 Agent

- 只有出现真实的共享决策、阻塞性依赖、权限控制或独立验收需要时，才增加协调角色或控制闸门。
- 按结果责任、决策权和交接承诺分工，不按“企业、部门、团队、个人”生成角色。
- Agent 提供临时观察或执行能力；治理层级由共享决策、阻塞依赖、权限和验收关系决定。
- 仅当探索彼此独立、原始材料远多于最终结论、且交接契约清晰时，才隔离探索上下文。
- 隔离探索只返回结论、证据位置、置信度和未解决项；主执行者不重复扫描同一范围。
- 并发写入共享工作区必须限定文件所有权；否则保持只读探索或顺序执行。

## Skill 路由

只选择当前突变和工作边界真正需要的最小组合：

| 发现 | 路由 |
|---|---|
| 关注点、用户证据或业务结果仍不成立 | 业务分析、用户研究或需求拷问 |
| 多个前例或概念需要合成为新方案 | `fusion` 或协作式构思 |
| 需要定义范围和可验收需求 | 产品需求或计划编写 |
| 界面行为成为关键机制 | 交互设计与设计评审 |
| 系统、数据或接口处发生机制突变 | 架构或 API 设计 |
| 敏感数据、外部动作或权限是关键约束 | 安全威胁建模与安全评审 |
| 工作边界已稳定，准备实现 | 实施计划与对应的工程、运营或变更能力 |
| 准备宣布完成 | `postflight` |

不要用“调用更多 skills”代替边界、责任、证据和验收。

## 输出

```markdown
**当前关注点**
- 正在理解、决定或改变的同一件事。

**缩放轨迹**
- 向外：关键目标、约束、影响和反馈。
- 向内：关键判断、动作、接口和完成证据。
- 横向：必须保留的重叠关系和共同约束。

**尺度不变量**
- 缩放过程中始终没有改变的核心结构。

**突变与紧耦合**
- 机制在哪里改变；哪些部分不能被任意切开。

**当前工作边界**
- 本次包含什么、排除什么；外部关系如何表达。

**治理与执行含义**
- 实际需要的责任、交接、控制闸门或上下文隔离。

**Skill 路由**
- 下一阶段的最小 skill 组合及各自交付物。

**停止理由与下一步**
- 为什么此刻不再放大或缩小；一个最小、可验证的动作。
```

## 红线

- 输出采用关系轨迹和临时工作边界，省略固定规模等级。
- 不按代码量、页面数、会议人数、角色数或 agent 数量放大问题。
- 保留重叠网络中的横向关系和循环反馈。
- 不因为“所有事物都有关联”而无限扩大范围。
- 观察尺度与权力高低、重要性排序分开表达。
- 不在业务问题尚未成立时进入实现。
- 不替方案、计划、实施或 `postflight` 宣布完成。
