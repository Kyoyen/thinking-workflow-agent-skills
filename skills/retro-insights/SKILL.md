# Retro Insights

## 定位

把多次协作转化为下一周期可验证的工作系统改进。

`preflight` 问：开始前应借鉴什么、避免什么、走哪条路？

`postflight` 问：这一次是否真的完成、可恢复、可维护、可交接？

`retro-insights` 问：跨多次任务后，什么模式正在重复，哪些改变值得进入规则、Skill、hook、runbook 或 automation？

不可替代边界：本 Skill 负责跨时间、跨项目、跨工具的反思和趋势闭环；不代替单次任务验收，不把 Git 指标当全部工作，不自动改写长期规则。

## 融合后的方法

这套方法吸收会话洞察、工程复盘、组织学习、`preflight` 与 `postflight` 的共同机制，再重组为宽口径方案：

- 从真实任务而不是印象中找使用模式；
- 同时观察代码、非代码、协作、环境和交付证据；
- 让长期教训可搜索、可过期、可撤回；
- 保持阶段边界、证据优先、最小下一步和选择性长久化。

舍弃 vanity metrics、分享卡片、纯提交量排名、自动把一次失败写入全局规则、只看 Git 仓库、长篇流水账和外部记忆服务依赖。

## 模式

| 用户输入 | 默认范围 | 重点 |
|---|---|---|
| `retro-insights` | 最近 7 天 + 最多 20 个实质用户根会话 | 周期性综合反思 |
| `retro-insights 24h/7d/30d` | 指定时间窗 | 时间趋势 |
| `retro-insights 20sessions` | 最近 20 个实质用户根会话 | 不受日期影响的协作样本 |
| `retro-insights compare` | 当前 7 天 vs 前 7 天 | 改进是否生效 |
| `retro-insights project <path>` | 指定项目 | 项目局部模式 |
| `retro-insights scheduled` | 最近 7 天并保存本地报告 | automation 周报 |

参数不明确时使用最近 7 天，不为低风险范围选择打断用户。

## 证据流水线

1. **确定窗口与问题**：明确是在看效率、质量、协作、工具稳定性、认知偏差、业务交付还是长期规则。
2. **读取用户根会话**：在有权读取且适配器可用时运行 `scripts/session_inventory.py`。默认排除子任务、自动化、空输入和技术探针。
3. **补工程趋势**：需要提交、测试、热点和趋势时，读取版本控制、测试与构建证据；不要用提交量直接代表价值。
4. **补非代码证据**：定向读取相关项目状态、handoff、postflight、运行日志、认证/网络检查和用户明确纠正。会话摘要和活动记录只作辅助线索。
5. **建立模式卡**：每个洞察记录证据次数、不同会话数、领域跨度、影响、置信度、反例和当前状态。
6. **区分层级**：事实、趋势、推断和建议分开；没有证据覆盖就明确写未知。
7. **提出最小改变**：每轮最多给 3 个行动，优先选择能在下一周期验证的改变。
8. **决定是否长久化**：按 `references/evidence-and-promotion.md` 的晋升门槛处理。
9. **下周期复核**：对上次行动标记 `有效 / 无效 / 未执行 / 证据不足`，避免每周重复同一句建议。

## 会话清单脚本

先定位 Skill。优先使用通用的 Agent Skills 目录：

```bash
RETRO_SKILL_DIR="$HOME/.agents/skills/retro-insights"
```

最近 7 天：

```bash
python3 "$RETRO_SKILL_DIR/scripts/session_inventory.py" --window 7d --limit 20 --format json
```

最近 20 个实质会话：

```bash
python3 "$RETRO_SKILL_DIR/scripts/session_inventory.py" --window all --limit 20 --format json
```

项目过滤：

```bash
python3 "$RETRO_SKILL_DIR/scripts/session_inventory.py" --window 30d --cwd-prefix "/absolute/project/path" --format markdown
```

脚本是面向 Codex 本地 session JSONL 的可选适配器。它只读原始会话，默认隐藏本地路径和真实会话标识，并对常见凭据、邮箱和用户目录做替换。它无法自动识别所有公司名、项目名或业务语义；任何输出在对外分享前都必须人工脱敏。需要更深证据时，只读取被选中的少量 session 文件。

## 默认观察维度

按证据选择，不强求全有：

- 工作分布：代码、产品/PM、协作平台/文档、设计、研究、环境/配置、自动化、交付。
- 成功模式：哪些路由、Skills、交付结构、验证方式持续有效。
- 反复摩擦：超时、重复重试、上下文污染、路径漂移、File Provider、依赖或入口问题。
- 用户纠正：术语、范围、顺序、审美、真实性、沟通方式和权限边界。
- 工具健康：Agent 客户端、协作平台、版本控制、provider、plugin、网络和认证的漂移。
- 证据质量：真实入口、人工试用、日志、测试、链接、截图、文件和待验证项是否匹配。
- 节奏与上下文：任务是否过长、是否多次压缩、是否应该新开任务或 handoff。
- 系统改进：规则、Skill、hook、runbook、automation、项目文档或无需改变。

## 模式晋升

默认不直接修改全局规则、项目规则、hooks 或 automation。

- 单次出现：记录为 `观察`。
- 两次出现：记录为 `关注`，寻找反例。
- 至少 3 个不同会话且跨 2 个领域，或用户明确确认：列为 `晋升候选`。
- 真正写入前：判断应进入全局规则、项目规则、Skill、hook、runbook、automation，还是只留报告。
- 写入后：下一周期验证是否减少同类问题；无效就回退或降级。

用户明确要求当场写入时可以执行，但仍要备份、最小 patch 和精确回读。

## 输出

默认使用短报告：

```markdown
**Retro Insights 范围**
- 时间/会话数/覆盖领域/证据缺口。

**本周期有效模式**
- 模式：证据、为什么有效、是否继续。

**重复摩擦与代价**
- 问题：出现次数、影响、根因置信度、反例。

**用户纠正与边界变化**
- 纠正：原行为、正确边界、是否已进入长期规则。

**系统健康与漂移**
- 工具/认证/代理/路径/Skill/自动化状态。

**晋升候选**
| 候选 | 证据 | 建议落点 | 置信度 | 状态 |

**下一周期实验**
1. 最多 3 个动作，写清验证信号。
```

对比模式增加“上周期建议是否生效”。没有可行动洞察时直接说没有，不硬造建议。

## 历史与周期化

- 交互调用默认在聊天中交付，不自动落盘。
- `scheduled`、`compare` 或用户明确要求保存时，将脱敏报告写入：

  ```text
  ./retro-insights-reports/
  ```

- 报告只保存主题、证据计数、洞察、行动和验证状态；不复制完整会话、tokens、cookies、账号标识或敏感业务正文。
- 周报适合每 7 天执行；规则晋升审查适合每月一次。周报只提案，月度审查再决定长期化。

## 路由

| 真正需要的是 | 路由 |
|---|---|
| 单仓库工程周报、commit/test/hotspot 指标 | 工程复盘与版本控制分析 |
| 跨工具、跨仓库工程趋势 | 跨仓库工程分析 |
| 搜索、清理或导出已保存教训 | 长期知识治理 |
| 单次任务验收、运维和交接 | `postflight` |
| 开始前找前例和最短路径 | `preflight` |
| 多个方案吸收成新方法 | `fusion` |
| 失败事件根因 | 根因分析、postmortem 或 AAR |
| 近期活动上下文 | 经过授权的活动记录；只作线索，不作完成证据 |

## 红线

- 不把 session 数、tokens、LOC 或 commit 数直接解释成产出质量。
- 不把 subagent、guardian、技术探针和 automation 当成用户有效会话。
- 不引用或导出完整敏感会话；默认用主题和证据计数。
- 不把活动记录或界面状态当成实施完成证明。
- 不因一次失败污染全局规则。
- 不自动上传报告或学习数据到外部服务。
- 不在没有用户批准时修改认证、网络、凭据存储或远端系统。
- 不把反思变成新项目；每周期最多 3 个改进动作。

需要判断证据强度、跨域重复和规则落点时，读取 `references/evidence-and-promotion.md`。
